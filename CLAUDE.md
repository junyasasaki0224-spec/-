# CLAUDE.md — あやかし釣り (Yokai Fishing)

Roblox game written in Luau, synced to Studio with Rojo. Japanese comments/docs; keep that style.

## Commands
- Build: `rojo build default.project.json -o YokaiFishing.rbxl`
- Format: `stylua src tests` (CI runs `stylua --check src tests`)
- Unit tests: `lune run tests/run.luau` (Config, Lib/Roll, Lib/Pricing, Lib/WorldClock, Lib/Format, Locale, FishBuilder)
- World smoke test: `lune run tests/world_smoke.luau` (Terrain calls are stubbed)
- Server integration: `lune run tests/server_sim.luau` — boots the real `src/server/init.server.luau` on fake Players/DataStore/remotes and plays through join → fish → sell → purchases → save. Add a case here when changing server logic. Note Lune quirks: set `Position` explicitly (not derived from CFrame), no Instance events (use fakes).
- Client UI simulation: `lune run tests/client_sim.luau` — runs the real Kit/Root/Online/Social/BattleUI on fake Instances with a manual clock (`advance(dt)`), feeds server messages and clicks buttons by their text. Add a case here when changing client screens.
- Whole client boot: `lune run tests/client_boot.luau` (and `DEVICE=phone ...`) — boots the real `init.client.luau` with every controller on fakes (`tests/fakes.luau`), replays real server messages recorded by `RECORD_MESSAGES=tests/fixtures/server_messages.json lune run tests/server_sim.luau`, opens every panel and presses every visible button, plays a fishing round, and checks layout (no overlap with the menu / Roblox jump button / top bar). Property names and value types are validated against Roblox's API (Lune reflection); unset properties return Roblox defaults. Re-record the fixture when server messages change.
- Economy pacing: `lune run tests/economy_sim.luau`

## Architecture
- `src/shared/Config/*` is the single source of game data. New fish/spots/quests = add rows, no code. `Config.Validate()` runs at server start and in tests.
- `src/shared/Lib/Roll.luau` and `Pricing.luau` are pure (rng is injected) so they can be unit-tested; keep them free of Roblox services.
- Server services live in `src/server/Services`, are wired in `src/server/init.server.luau` through a registry `S` (`S.Data`, `S.Fishing`, …) with `init(S)` then `start()`. Do not `require` services from each other directly (avoids cycles); use `S`.
- All client→server traffic goes through `RemoteGuard.connect` (rate limit + pcall). Shop/settings actions share the `Request` remote and are routed by `handleRequest`.
- Client modules in `src/client/Controllers` only render and send intents. UI is built in code via `src/client/UI/Kit.luau`.
- Online (max 10 per server, `Config/Online.luau`): `PvpService` (challenges by userId with all/friends/off preference, random queue by power, falls back to an anonymous team snapshot from another server stored in MemoryStore keyed by userId; Elo in `Lib/Rating`; forfeits are recorded via `DataService.onRelease` before the save), `RaidService` (co-op boss rooms up to 4, one shared HP pool, `Config/Bosses.luau`), `SocialService` (fixed stamps only, public attributes). Client: `Controllers/Online.luau` (arena state, invite/recruit cards, status pills), `Controllers/Social.luau` (なかま panel, stamps), `BattleUI` hub tabs. No custom text chat. See docs/ONLINE.md.
- Partner battles: data in `Config/Battle.luau` + `Config/Trainers.luau`; pure engine `Lib/Battle.luau` (stats, moves, damage, turn resolution, AI; rng injected). `PartnerService` (add/feed/team/lock) and `BattleService` (one server-side battle session per player, `BattleAction` remote in, `BattleState` remote out). Client `Controllers/BattleUI.luau` only replays server events; the stage is a real 3D underwater arena built client-side in Workspace (`Controllers/BattleArena.luau`, pure Instance code with shared camera/home math; `BattleScene.luau` takes the camera (Scriptable), swaps Lighting to an underwater look and restores it, pauses `LightingFX.hold`, plays 3D effects). Moves are talisman cards (keys 1–4, gamepad D-pad); `Lib/BattleAdvice.luau` suggests a move (★ / おまかせ). Preview without Studio: `lune run tools/battle/export_battle.luau build/battle.json` then `python tools/battle/render_battle.py build/battle.json out` (Blender, real fish meshes). See docs/BATTLE.md.
- Fish visuals: `Lib/FishBuilder.luau` uses anime meshes from `ReplicatedStorage.FishMeshes` (imported in Studio from `assets/fish/YokaiFishMeshes.glb`, made by `tools/blender/yokai_fish.py`) and falls back to the part-built fish when absent. Sizes come from `Config/FishMeshes.luau` (generated, scaled by height). Rarity flair that is not in the mesh (aura, lights, fire, mutation tint shell) is added in code. Imported fish carry a `SurfaceAppearance` (1024px color + normal map baked from an 80k–180k-tri sculpt); outline, tint shell and silhouette strip it. Each game mesh is decimated to ≤ 15k tris; `export_fish` fails the build if any mesh exceeds Roblox's 20k limit.
- Fish cries: `tools/cries/yokai_cries.py` (numpy synth, one recipe per fish) writes one audio sprite `assets/sounds/YokaiCries.ogg` and `Config/Cries.luau` (start/length + ja/en bubble text, `soundId` set by hand after upload; `audioHash` resets it when the audio changes). `Lib/Cries.luau` looks up regions; client `Controllers/Cry.luau` plays the region (`PlaybackRegion`) and shows the bubble. Cries are client-only cosmetics.
- Gacha (百鬼の祠): `Config/Gacha.luau` (rates, pity 10/90, earn table), pure `Lib/Gacha.luau` (rng injected), `GachaService` (`gachaPull` with 1 or 10 only; pays tickets then magatama; `GachaService.give` is the one way to grant currency), client `Controllers/Gacha.luau` (panel + reveal). Shrine-only fish live in `Config/Fish/Shrine.luau` (`spot = "shrine"`, `limited`, `signature` move ≤ power 75 so paying does not win PvP). Odds are always shown; Robux packs are hidden when `PolicyService` says paid random items are restricted. See docs/GACHA.md.
- BGM: `tools/music/yokai_bgm.py` (numpy synth, Japanese scales) writes `assets/sounds/bgm/*.ogg` and `Config/Music.luau` (per-track `soundId` set by hand after upload, reset by `audioHash`). Client `Controllers/Music.luau` plays the nearest spot's track, BattleUI calls `Music.battle(true/false)`, crossfades. See docs/MUSIC.md.
- World is generated at runtime (`src/server/World`): Terrain + Parts. Text on signs/prompts is localized on the client via the `LocKey` attribute. Each area is a valley ringed by mountains (`Terrain.build` with `ring`/`ringHeight`) with invisible `Scenery.boundary` walls; paths are painted terrain (`Terrain.paintPath`), scenery pieces live in `World/Scenery.luau`. `world_smoke` checks every prompt/spawn is ≥10 studs inside the walls. Preview the map without Studio: `lune run tools/map/export_map.luau build/map.json` then `python tools/map/render_map.py build/map.json out` (Blender/bpy). See docs/MAP.md.

## Rules (security / privacy)
- Server decides every outcome (fish, weight, mutation, price, rewards). Never accept these from the client.
- Validate every remote argument with `RemoteGuard.isNumber/isInt/isId`; reject NaN/inf/long strings.
- Store only game progress keyed by UserId. No names, chat, device info. Pass `{ userId }` to UpdateAsync for GDPR erasure; keep `DataService.eraseUser` working.
- `ProcessReceipt`: grant → record PurchaseId → save → only then `PurchaseGranted`.
- No user-typed text is shown to others; if that is ever added it must go through TextService filtering.
- Never commit secrets (.env, API keys). Product IDs are public and live in `Config/Products.luau`.
