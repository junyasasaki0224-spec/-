# セキュリティと個人情報の方針

## 1. 不正(チート)対策 — 「サーバーがすべてを決める」

| 項目 | 方法 | 場所 |
| --- | --- | --- |
| 釣れる魚・重さ・変異・売値 | サーバーが抽選・計算。クライアントは結果を受け取るだけ | `FishingService`, `ShopService` |
| 投げる | 送れるのは「強さ 0〜1」と「向き」だけ。水辺から 14 スタッド以内か、解放済みの釣り場か、魚籠に空きがあるかをサーバーで確認 | `FishingService` |
| 合わせ | 「!」を出した時刻をサーバーが記録し、猶予(1秒+通信の遅れ0.45秒)を超えたら無効 | `FishingService` |
| 引き上げ | 成功の報告が「完璧に操作しても不可能な速さ」なら却下し、分析に `SuspiciousReel` を記録 | `FishingService.finishReel` |
| 同時に何匹も釣る | 1人1つの状態+トークンで管理。古いタイマーは無視 | `FishingService` |
| 連打・スパム | 通信ごとにトークンバケットで回数制限。ハンドラのエラーは pcall で隔離 | `RemoteGuard` |
| 不正な値 | NaN・無限大・範囲外・長い文字列・未知のIDを拒否 | `RemoteGuard.isNumber/isInt/isId` |
| 売る | 魚屋(狸の行商)の近くでないと売れない。変異つきは一括売却の対象外(うっかり防止) | `ShopService` |
| ぬし釣り | 報告は「枠に入っていた秒数」だけ。経過時間×上限でしか加算されず、湖の近くにいる必要あり | `NushiService` |
| 自動釣り | パス所持をサーバーで確認し、サーバー内だけで完結 | `FishingService.autoStep` |

## 2. データ保存

- **セッションロック**: サーバーを素早く移動した時に、古いサーバーの保存が新しい進行を上書きしないよう、データにロック(サーバーID+時刻)を持たせています。ロックを失ったサーバーは保存を止めてプレイヤーに再参加を促します。
- **自動保存** 90秒ごと / 退出時 / サーバー終了時(`BindToClose`)。
- **課金の二重付与防止**: 購入ID(PurchaseId)を最大100件記録し、付与→記録→保存成功の後にだけ `PurchaseGranted` を返します。
- 読み込みに失敗した場合、本番では「再参加してください」と表示してキック(壊れたデータで上書きしないため)。Studio では保存しない一時データで遊べます。

## 3. 個人情報

- 保存するのは **ゲームの進行データだけ**(キーは `u_<UserId>`)。名前・チャット・端末情報・位置情報などは保存しません。
- ランキングに保存するのは UserId と数値だけ。表示名は表示の時に Roblox の公開ユーザー名を取得します。
- 小屋の看板・サーバー大漁のお知らせには Roblox の表示名(Roblox 側でフィルタ済みの公開情報)だけを使います。
- プレイヤーが自由に文字を入力して他の人に見せる機能はありません(フィルタ漏れの心配がない)。将来追加する場合は必ず `TextService:FilterStringAsync` を通すこと。
- 外部への通信(HttpService)は使っていません。分析は Roblox 標準の AnalyticsService だけです。

### データ削除の依頼(Right to Erasure)が来たら

Roblox からメッセージで削除依頼(UserId つき)が届いたら、Studio でゲームを開き、コマンドバーで次を実行します(API アクセスを有効にしておくこと):

```lua
require(game.ServerScriptService.Server.Services.DataService).eraseUser(依頼のUserId)
```

プレイヤーデータとランキングの記録が削除されます。保存時に UpdateAsync へ UserId を渡しているので、Roblox 側の DataStore でも対象のデータとして紐付いています。

## 4. 秘密情報

- Open Cloud の API キーなどはリポジトリに入れません(`.gitignore` で `.env` などを除外済み)。
- 課金商品の ID は公開情報なので `Config/Products.luau` に書いて問題ありません。
