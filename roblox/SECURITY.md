# Roblox 版の守り(セキュリティの見直し 2026-11-19)

## 決まり

- お金(コイン)・持ち物・購入・着順・レート・沈没などの判定は、すべてサーバーが行う。プレイヤー側は表示と入力だけ。
- プレイヤー側から届く合図(RemoteEvent・RemoteFunction)は、サーバーで次を確かめて、合わない物は無視する。
  - 型
  - 範囲
  - 長さ
  - 回数(時間あたり)
- 秘密の情報(API キーなど)は、ファイル・ReplicatedStorage・プレイヤー側に置かない。オーナーのアカウントの番号やメールアドレスも、ファイルに書かない。
- Robux で売るのは、ガチャのコインの袋と VIP パス。コインはガチャ(ランダム)に使うので、地域の決まり(PolicyService)で売れない人には売らない。確率は引く前に画面に出し、表示と抽選は同じ表(`Meta.RARITY` と品の数)から作る。ガチャは種類(艇外装・ヘルメット・モーターカバー・ステアリング・艇首旗)を選んでから、その30点の中で引く。

## 会場に入る時

移動の情報(TeleportData)はプレイヤー側を通るので、書き換えられる前提で扱う。

- 部屋・ランク戦・大会では、移動の情報だけでは入れない。サーバー側の記録で入る人を確かめる。
  - 部屋: 合言葉の記録。
  - ランク戦: 待ち行列の記録。
  - 大会: 大会の記録と、予約した会場の番号。
- 1人用の会場(フリーレース・練習・タイムアタック)は、値をすべて範囲で確かめる。範囲の外なら外に出す。

## 購入(ShopService)

- 品を渡すのは `MarketplaceService.ProcessReceipt` の中だけ。プレイヤー側の「買った」という知らせは使わない。
- 保存できた時だけ `PurchaseGranted` を返す。保存できなければ `NotProcessedYet` を返す(Roblox があとでもう一度届ける)。
- 同じ購入番号は1回だけ渡す(持ち物の記録に購入番号を残す)。知らない製品の番号は渡さずに残す。
- VIP パスは、入った時と買った直後に、Roblox に「持っているか」を聞き直してから渡す。
- 持っている VIP パスは、ショップの画面で買えないようにしてある。
- コインの袋の購入画面はサーバーが出す。画面からは袋の名前(`c1`〜`c4`)だけを受け取り、名前・長さ・回数(1秒に1回)を確かめる。
- コインはガチャに使うので、`PolicyService` の `ArePaidRandomItemsRestricted` を確かめる。確かめられない時は「買えない」として扱う。買えない人には購入画面を出さず、VIP のコインの特典も付けない。
- VIP の毎日のボーナスは、日付ごとに1回だけメールで届く(サーバーで日付を覚える)。
- ランク戦の1日5回は、ロビーのサーバーが受付の時に保存された回数で確かめる(回数はレースの結果を保存する時に数える)。

## 確かめた結果(今回)

- 秘密の情報・オーナーの番号・メールアドレスはファイルにない(`git grep` で確認)。`loadstring`・`getfenv`・外部への HTTP 通信は、ゲームのコードで使っていない。
- 大会の受付で、文字の長さを確かめていなかったので、64字までにした。
- ほかの受付には、型・範囲・回数の確認がすでにあった。
