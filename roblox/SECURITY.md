# Roblox 版の守り(セキュリティの見直し 2026-11-19)

## 決まり

- お金(コイン)・持ち物・購入・着順・レート・沈没などの判定は、すべてサーバーが行う。プレイヤー側は表示と入力だけ。
- プレイヤー側から届く合図(RemoteEvent・RemoteFunction)は、サーバーで次を確かめて、合わない物は無視する。
  - 型
  - 範囲
  - 長さ
  - 回数(時間あたり)
- 秘密の情報(API キーなど)は、ファイル・ReplicatedStorage・プレイヤー側に置かない。オーナーのアカウントの番号やメールアドレスも、ファイルに書かない。
- Robux で売るのは、ガチャのコインの袋と VIP 会員(サブスクリプション)。コインはガチャ(ランダム)に使うので、地域の決まり(PolicyService)で売れない人には売らない。確率は引く前に画面に出し、表示と抽選は同じ表(`Meta.RARITY` と品の数)から作る。ガチャは種類(艇外装・ヘルメット・モーターカバー・ステアリング・艇首旗)を選んでから、その30点の中で引く。

## 受付ごとの確かめ

| 合図 | 場所 | 確かめていること |
|---|---|---|
| `MinatoMeta` | ロビー | 操作の名前が決まった物だけ。<br>0.35秒に1回・同時に1つ。<br>使い回しを防ぐ札(token)。<br>文字は80字まで。<br>ガチャは「種類:回数」の形だけ(種類は5つのどれか、回数は1か10。`Meta.pullArg`)。<br>装備は持っている品だけ。<br>設定は決まった名前と値だけ(ヘルメットの目元 `visor` も on / off だけ)。 |
| `MinatoInput` | 会場 | 数(NaN 以外)。<br>スロットルは 0〜1、ハンドルは -1〜1。<br>順番の番号が増えていること。<br>0.04秒に1回。<br>今のレースの番号。 |
| `MinatoSetup`(チルト) | 会場 | 1〜4 の整数。<br>スタート前だけ。<br>アクセルを踏んだら変えられない。<br>0.2秒に1回。 |
| `MinatoRoomRace` | 会場 | 操作ごとに次を確かめる。<br>・その人が会場の参加者か。<br>・部屋の主か。<br>・今の段階で使える操作か。<br>スキップは全員の票。 |
| `MinatoRoomLobby` | ロビー | 5秒に1回。<br>作るか入るかだけ。<br>合言葉は6文字(紛らわしい文字を除く)。 |
| `MinatoFreeRace`・`MinatoTimeAttack` | ロビー | 1秒・0.8秒に1回。<br>コース・チルト・難易度・時間帯・種をすべて範囲で確かめる。 |
| `MinatoRankedLobby` | ロビー | 決まった操作だけ。<br>2秒に1回。<br>ランク戦は保存された今日の回数で1日5回まで(VIP は無制限)。 |
| `MinatoShop` | ロビー | 「買いたい」だけ。<br>袋の名前は決まった物(8字まで)。<br>1秒に1回。<br>地域の決まりを確かめてから購入画面を出す。 |
| `MinatoTournament` | ロビー | 決まった操作だけ。<br>書き換えは0.6秒に1回、読むのは0.2秒に1回。<br>文字は64字まで(今回追加)。<br>大会名は Roblox の文字の検査(TextService)を通す。<br>開始・中止は主催者だけ。 |
| `MinatoEventBoard`・`MinatoLeaderboard` | ロビー | 0.5秒・1秒に1回。<br>読むだけ。 |

## 会場に入る時

移動の情報(TeleportData)はプレイヤー側を通るので、書き換えられる前提で扱う。

- 部屋・ランク戦・大会では、移動の情報だけでは入れない。サーバー側の記録で入る人を確かめる。
  - 部屋: 合言葉の記録。
  - ランク戦: 待ち行列の記録。
  - 大会: 大会の記録と、予約した会場の番号。
- 1人用の会場(フリーレース・練習・タイムアタック)は、値をすべて範囲で確かめる。範囲の外なら外に出す。

## 購入(ShopService)

- 品を渡すのは `MarketplaceService.ProcessReceipt` の中だけ。プレイヤー側の「買った」という知らせは使わない。
- 保存できた時だけ `PurchaseGranted` を返す。保存できなければ `NotProcessedYet` を返す(Roblox があとでもう一度届ける)。
- 同じ購入番号は1回だけ渡す(持ち物の記録に購入番号を残す)。知らない製品の番号は渡さずに残す。
- VIP 会員かどうかは、サーバーが Roblox に聞いて決める(`GetUserSubscriptionStatusAsync`)。入った時・10分ごと・購入の画面が閉じた時・会員の状態が変わった時に聞き直す。画面からの知らせは使わない。
- 会員でないと確かめられたら、保存の印を外し、着ていた VIP の品をスタンダードに戻す。会場のサーバーも、レースの前に確かめる(招待から直接会場に来た人も)。聞けなかった時は、今の状態のままにして次にもう一度聞く。
- VIP の品は持ち物の記録に入れない(会員の印がある間だけ使える。`Meta.owns`)。
- 会員の間は、ショップの画面で会員の購入ボタンを押せないようにしてある。初めて会員になった時のコインは、一人1回だけ(購入番号 `sub:welcome` を覚える)。
- コインの袋の購入画面はサーバーが出す。画面からは袋の名前(`c1`〜`c4`)だけを受け取り、名前・長さ・回数(1秒に1回)を確かめる。
- コインはガチャに使うので、`PolicyService` の `ArePaidRandomItemsRestricted` を確かめる。確かめられない時は「買えない」として扱う。買えない人には購入画面を出さず、VIP のコインの特典も付けない。
- VIP の毎日のボーナスは、日付ごとに1回だけメールで届く(サーバーで日付を覚える)。
- ランク戦の1日5回は、ロビーのサーバーが受付の時に保存された回数で確かめる(回数はレースの結果を保存する時に数える)。

## 確かめた結果(今回)

- 秘密の情報・オーナーの番号・メールアドレスはファイルにない(`git grep` で確認)。`loadstring`・`getfenv`・外部への HTTP 通信は、ゲームのコードで使っていない。
- 大会の受付で、文字の長さを確かめていなかったので、64字までにした。
- ほかの受付には、型・範囲・回数の確認がすでにあった。

## 見直し(2026-11-24): 全体のセキュリティ・個人情報・著作権

### 確かめた所

- 合図の受付(13個)を全部読み直した: `MinatoMeta`・`MinatoShop`・`MinatoFreeRace`・`MinatoTimeAttack`・`MinatoRoomLobby`・`MinatoRankedLobby`・`MinatoTournament`・`MinatoEventBoard`・`MinatoLeaderboard`(ロビー)、`MinatoInput`・`MinatoSetup`・`MinatoRoomRace`・`MinatoRoomInfo`(会場)。型・範囲・長さ・回数の確認は、下の2つ以外はそろっていた。
- 購入(`ShopService`): 渡すのは `ProcessReceipt` の中だけ・保存できた時だけ `PurchaseGranted`・同じ購入番号は1回だけ・地域の決まり(`PolicyService`)を確かめてから購入画面、を確認。問題なし。
- ガチャ: 確率の表示と抽選が同じ表(`Meta.RARITY` と品の数)から作られていることを確認。
- タイムアタックの記録: サーバーが入力の列から走りを再現して、タイムが一致した時だけ登録している。問題なし。
- アバターの人形: Roblox から作った人形のスクリプトを消してから使っている。問題なし。
- 文字: プレイヤーが書いた文字を他の人に見せるのは大会名だけで、Roblox の文字の検査(`TextService`)を通している。リッチテキストは使っていない。外部サイトへの案内もない。
- 秘密の情報・個人情報: 管理中の全ファイル(画像・音・模型の中の作者情報も)と、GitHub に送った全ブランチの全履歴を調べた。API キー・パスワード・Studio のアカウント名・ユーザー番号・場所の番号は入っていない。FBX の作者欄も空。
- データ削除(`DATA_DELETION.md`): 保存先の全部(DataStore 12個・MemoryStore 4種類)が載っていることを確認。`MinatoStats_v1` の中身の説明を今の中身(コイン・持ち物・購入の記録など)に直した。
- 開発用の道具(`roblox/tools`・`tools`): 通信の受け口はこの PC の中(127.0.0.1)だけ。

### 見つけて直した所

1. **持ち物の合図(`MinatoMeta`)の連打で、サーバー全体の保存が詰まるおそれ**: 読み直し(get)も含め、操作のたびに保存(UpdateAsync)を1回使っていて、0.35秒に1回まで通していた。保存にはサーバー全体で1分あたりの上限(8人なら約140回)があり、1人が押し続けるだけで、ほかの人のレース結果や Robux の購入の保存が遅れうる。
   → 1人ぶんの書き込みを回数券で抑えた(続けて10回、そのあとは3秒に1回。1分に約20回まで)。読み直しは5秒のあいだ前に返した物を使い回す(購入や VIP のボーナスで中身が変わった時は使い回さない)。`MetaLobby.server.lua`・`MetaService.lua`
2. **会場にロビーを通らずに入れた時の守りが、Roblox の設定だけだった**: 会場の予約していないサーバー(公開・VIP サーバー)では、入場の確かめなしでレースが走り、結果(コイン)が保存されていた(PUBLISH.md 手順6の「Secure within universe only」を忘れると入れる)。
   → 本番の会場で予約していないサーバーに入った人は「ロビーから入り直してください」で外に出す。結果の保存も、サーバーが入場を確かめてモードが決まった会場だけにした。`Race.server.lua`
3. **持っていない品を装備したままになりうる**: 読み込み時の整え(`Meta.normalize`)は「品があるか」だけを見ていた。検証用の「全部の品を解放」(`TEST_UNLOCK_ALL`)を止めた後も、持ち主が借りていた品を着たままになる。
   → 持っていない品を装備していたら、スタンダードに戻す(解放がオンの間だけはそのまま)。持ち物の記録が壊れていても止まらないようにした。テストを追加(`tests/meta.spec.luau`)
4. **大会の受付で、とても長い文字を整える前に断っていなかった**: 大会名は整えてから20文字か確かめていたので、とても長い文字を送られると、その分だけサーバーが働く。参加の大会番号(表の中の文字)も長さを見ていなかった(保存先の手前では断っていた)。
   → 大会名は 240 バイトより長ければすぐ断る。参加の大会番号も 64 文字まで。テストを追加(`tests/tournament.spec.luau`)
5. **録音を受け取る道具(`roblox/tools/receive_wav.py`)が、どのサイトからでも受け付けていた**: 動かしている数秒のあいだに、ブラウザで開いている別のサイトからも送れた。
   → この PC の中のページ(ファイルで開いたページ・localhost・127.0.0.1)からだけ受け付け、中身が WAV でなければ保存しない。

### オーナーがやること(コードでは直せない所)

- **GitHub のリポジトリが「公開」になっている**: コード・文書・素材を誰でも見られる(サーバーの守りの作りも読める)。GitHub の Settings → General のいちばん下(Danger Zone)の「Change visibility」で **Private** にするのがおすすめ。
- 公開の前に `MetaService.lua` の `TEST_UNLOCK_ALL` を false にする(PUBLISH.md)。
- 会場の場所の設定で「Secure within universe only」を選ぶ(PUBLISH.md 手順6。今回コードでも二重に守った)。
